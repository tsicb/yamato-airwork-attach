# yamato-airwork-attach

ヤマト運輸向けの **AirWork広告実績CSV → 通常応募CSV_Aへの行追加ツール**です。既存の [valid-app](https://github.com/tsicb/valid-app) には手を加えません。

## 目的

通常応募CSVに含まれないAirWork実績の応募数を、日ごとに「1応募＝1行」に展開し、**1つの統合応募CSV**としてvalid-appに取り込みます。AirWork以外の応募との月別・日別・曜日別・媒体別比較を可能にし、求人や応募者の詳しい属性は別枠・不明として扱います。

## 使い方

1. index.html をブラウザで開く（GitHub Pages設定後は公開ページを使用）。
2. 通常の応募CSV（**「お仕事NO」列のあるCSV_A形式**）を選択する。
3. AirWork広告詳細CSV（**「配信日」「応募数」列**）を選択する。
4. 通常CSVに複数企業コードがある場合、AirWork実績の追加先を選択する。1社だけなら自動選択。
5. 仮想仕事番号（初期値 AIRWORK_ONLY）を確認して「統合内容を確認」を押す。
6. **通常件数＋AirWork追加件数＝統合後件数**を確認してダウンロードする。
7. ダウンロードした**統合CSVのみ**をvalid-appへ読み込む。

**元の通常応募CSVを同時にvalid-appにアップロードすると二重計上されます。** また、AirWorkの実応募が元の通常CSVにも含まれていた場合は、元データとの重なりを本ツールで識別できないため、利用前に確認してください。

## 変換仕様

| 項目 | ルール |
|---|---|
| 入力通常CSV | 「お仕事NO」、「企業コード」または「企業ID」、「応募日時」または「応募日」、「氏名」または「応募者名」が必要 |
| 入力AirWork CSV | 「配信日」と「応募数」が必要 |
| ファイルの文字コード | UTF-8（BOM付き・なし）、Shift_JIS（CP932）をブラウザで自動判定 |
| AirWorkの「合計」行 | 行追加せず、日別合計との照合に利用（不一致はエラー） |
| 空の応募数・負数・小数 | エラー。0件の日は追加なし |
| 配信日 | YYYY/MM/DD または YYYY-MM-DD。日付のみを応募日時に出力（時刻は創作しない） |
| 応募数 | 指定数だけ同一日付の応募行を追加 |
| 企業コード | 指定した元CSV内の企業コード |
| お仕事NO | AIRWORK_ONLY（設定変更可）。既存求人と関連付けしない |
| 仕事名 | AirWork（応募実績） |
| 職種・雇用形態・求人勤務地名称・募集背景 | AirWork（詳細不明） |
| 応募媒体 | AirWork |
| 対応状況 | AirWork（状況未取得）（有効応募とはみなさない） |
| 氏名・年齢・居住住所 | 空欄。氏名はvalid-appの重複除外条件を満たさないため、生成行が誤ってまとめられない |
| 性別 | 既存列がある場合のみ「不明」 |
| 求人勤務地住所・都道府県・給与・画像・求人タグなど | 未取得のため空欄 |
| CSVの構成 | 元CSVのヘッダー・列順・行を保持し、不足している必要列を末尾に追加してAirWork行を末尾に並べる |
| 出力 | UTF-8 BOM付き、CRLF区切りCSV。ファイル名は application_with_airwork_YYYYMMDD.csv |
| 大量データ | 入力1ファイル30MB、出力合計25万応募行まで |

通常応募CSVに同じ企業コード・仮想仕事番号が存在すると、二重追加を防ぐため処理を停止します。**統合済みCSVを再度通常入力に使わず、必ず元のCSVを使ってください。**

## valid-appレポートとの関係

- 全体応募数、応募年月・日付・曜日、応募媒体など、**応募データを母集団とする分析**にAirWork行を追加します。
- 年代は年齢不明なので「その他」等、性別は「不明」、対応状況は「AirWork（状況未取得）」として表示します。
- 仮想求人の属性（職種、雇用形態、勤務地名など）は、応募CSV内の求人情報によるフォールバック経路を利用し、「AirWork（詳細不明）」として表に登場するようにします。
- 給与・画像・求人タグ等、**求人CSV突合済み応募のみを母集団とする分析**にはAirWork応募は含まれません。
- **年齢の全体フィルターを有効にすると**年齢不明のAirWork応募が対象外になり、総応募数にも入りません。
- 仮想仕事番号は1求人として扱われるため、**1求人あたり応募数**などの指標の母数に影響する場合があります。
- 元CSVに応募者重複があるとvalid-app自身の重複除外処理により、単純な「通常CSV行数＋AirWork追加行数」とレポートの表示件数が一致しない場合があります。

## セキュリティと公開方法

ブラウザ内部のみでCSVを解析・生成します。ファイルをサーバー、GitHub、Google Drive等へアップロードするコードはありません。個人情報を含むサンプルCSVはリポジトリにコミットしないでください。

静的ファイル index.html、app-core.js のみで動作し、外部ライブラリ・ビルド・サーバー・アクセスキー不要です。

**GitHub Pages設定手順：**

1. リポジトリの **Settings → Pages** を開く。
2. **Build and deployment → Deploy from a branch** を選択。
3. Branch main、Folder /(root) を選択して **Save**。
4. 公開後、https://tsicb.github.io/yamato-airwork-attach/ から利用する。

GitHub Pagesを有効化する前でも、2つのファイルを同じフォルダにダウンロードすれば index.html から利用できます。

## 開発とテスト

Node.js 22以降で、外部パッケージ不要です。

    node --test tests/*.test.cjs

GitHub ActionsのCIではpush・PRごとに同じテストを実行します。

### 初版の対象外

- AirWork実績と通常応募CSVの同一人物・同一応募判定（照合キーがないため）。
- AirWorkレポートから個別求人や応募者属性を推測する処理。
- valid-appのコード・分析表・マスタ設定への変更。
- サーバー保存や自動同期。
